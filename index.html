Un libro interactivo sobre peticiones HTTP con Python y requests

Python es, quizás sin proponérselo, el lenguaje más usado para hablar con servicios web. Su librería requests reduce una petición HTTP completa —método, encabezados, cuerpo— a una sola línea de código, y su respuesta a un simple diccionario.

Eso no significa que no haya nada que entender debajo. Cada llamada a requests.post() dispara un ciclo completo de petición y respuesta, con un código de estado que dice si algo salió bien y un cuerpo que trae los datos de vuelta.

En este capítulo vas a mandar una petición real a un servidor real —httpbin.org— y vas a ver esa respuesta encender un LED fuera del propio código.

CAPÍTULO I · ≈ 4 MIN

¿Qué es una API?

API —Application Programming Interface— es el conjunto de reglas que le permite a un programa pedirle algo a otro sin conocer su código interno. Una API web es, en concreto, un servidor que escucha peticiones HTTP y responde con datos, casi siempre en JSON.

Clientetu script de Python (o el navegador).
Servidorla API que recibe la petición y decide qué responder.
HTTPel protocolo de transporte: GET, POST, PUT, DELETE.
JSONel formato en el que viajan los datos, en ambas direcciones.

Toda petición sigue el mismo ciclo:

import requests

r = requests.get("https://httpbin.org/get")
print(r.status_code)   # 200
print(r.json())        # dict con la respuesta
CICLO PETICIÓN–RESPUESTA

El cliente envía la petición, el servidor la procesa, y regresa un status code junto con un cuerpo. r.status_code te dice si salió bien; r.json() te da los datos.

200 significa éxito, 404 que el recurso no existe, 500 que el servidor falló — llegan siempre en respuesta.status_code.

SIMULA LA PETICIÓN

terminal

$ python peticion.py

requests.get("https://httpbin.org/get")

Status: 200 → sin cuerpo enviado, solo pides datos.

GET no manda cuerpo; POST sí, y httpbin te lo regresa dentro de "json".

CAPÍTULO II · ≈ 4 MIN

La librería requests

pip install requests

requests.post() hace tres cosas por dentro: arma la petición (encabezados y cuerpo), la envía por la red, y convierte la respuesta de vuelta a un diccionario de Python con .json().

import requests

respuesta = requests.post(
    "https://httpbin.org/post",
    json={"led": "on", "mensaje": "hola"}
)
print(respuesta.status_code)
print(respuesta.json())
200
{'json': {'led': 'on', 'mensaje': 'hola'}}
QUÉ ES HTTPBIN

httpbin.org, creado por Kenneth Reitz —el mismo autor de requests—, no hace nada más que eco: te regresa exactamente lo que le mandaste, dentro de la clave "json".

Con json=, requests serializa el diccionario y agrega el encabezado Content-Type: application/json automáticamente.

Cómo viaja el mensaje

postMessage permite que dos ventanas se comuniquen aunque estén en dominios distintos. El cuaderno de Colab corre dentro de un <iframe>; al llamar window.parent.postMessage(estado, "*"), esta página —la ventana que contiene ese iframe— recibe el mensaje y actualiza el LED.

httpbin no guarda nada de lo que le mandas: solo confirma que tu petición llegó bien formada antes de que hables con una API de verdad.

GOOGLE COLAB · RETO

import requests

estado = "off"   # 👈 Tu reto: escribe "on"

# ==================================================
# Envía el estado a la API
# ==================================================
url = "https://httpbin.org/post"

respuesta = requests.post(
    url,
    json={"led": estado}
)

# ==================================================
# Comprueba la respuesta
# ==================================================
print("Código de respuesta:", respuesta.status_code)

datos = respuesta.json()

print("Datos enviados a la API:")
print(datos["json"])

if estado == "on" and datos["json"]["led"] == "on":
    print("\n🎉 ¡RETO SUPERADO!")
    print("🔴 El LED debería estar encendido.")
else:
    print("\n💡 Aún no.")
